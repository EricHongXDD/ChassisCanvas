# 微雪屏端麦克风识歌模式

> **实验/研究文档。** 该模式不进入 Windows 正式包，不是产品安装步骤、
> 默认配置或验收前置。正式方案不使用麦克风、识歌、屏端联网或屏端 Cookie。

## 状态与适用范围

`standalone-recognition` 是微雪屏端自行采样、通过 HTTPS 识别歌曲、在 TF 缓存歌词并以本机时间轴滚动的条件式实验模式。它不依赖 Windows GSMTC 或 Windows 常驻服务，但依赖真实可用的屏端麦克风、独立网络、信任环境和识歌中继。

当前仓库包含状态机、自托管 HTTPS relay、协议、镜像补丁与失败回退所需代码及自动化测试；这不等于 7 英寸或 8.8 英寸真机已经通过验收。对两份原图和两份干净 8 GB 扩容图的静态审计进一步确认：两型号使用同一份 rootfs 和 kernel，扩容只增大 UDISK/GPT；内核没有编入常见 SDIO/USB Wi-Fi 驱动，`/lib/firmware` 为空。Windows 上已连接的 7 英寸当前也只枚举一个 ACM 串口接口，没有原厂启用的 RNDIS/USB 网卡接口。因此原镜像本身不能直接生成并宣称“插电即可独立识歌”的最终镜像。

7 英寸设备树虽然启用了 GMAC/RMII，但官方外观与说明没有证明板上存在 PHY、磁性器件或可用网口；8.8 英寸的同一 GMAC 节点还是 `disabled`。镜像中的 `wpa_supplicant`、`iw`、`udhcpc` 和示例脚本只是通用用户态工具，不会凭空增加无线芯片、驱动、固件或天线。不过内核已经编入 configfs ACM、RNDIS 和 `u_ether` Gadget，用户态也有 `udhcpc`。因此现在提供两种严格区分的联网门禁：真机验证过的物理网卡，或 `usb-gadget-bridge` 专用外置 USB Host/Wi-Fi 小桥。后者完全不使用电脑，但属于明确列出的额外硬件，不能冒充板载 Wi-Fi。

资源和可靠性优先时，仍应选择 [Windows 主机 GSMTC + USB 小包](standalone-lyrics.md)。

## 数据流

```text
屏端麦克风
  -> ALSA arecord：1 秒 / 16 kHz / mono / S16_LE
  -> 20 ms 能量 VAD
  -> 10 秒 PCM 环形窗口（仅 RAM，约 320 KiB）
  -> ARM32 紧凑 fingerprint 提取器（优先）
     或 10 秒 PCM JSON（显式高带宽兼容回退）
  -> HTTPS recognition-v1 relay + Bearer 设备 token
  -> stable_id / ISRC / offset / confidence
  -> 仅接受可靠映射并标记 native_id_verified 的 source + track_id
  -> 对应平台精确歌词接口
  -> TF 歌词缓存
  -> 本机单调时间锚点选择 current / next
  -> 原厂 PCMonitorLinux 驻留 Theme
```

识歌中继保存第三方 ACR/识歌服务主密钥。副屏只保存逐屏唯一、可单独撤销的 relay token，不能把第三方主密钥写入公共 IMG。

仓库内的自托管服务、令牌摘要格式、ACRCloud provider、强映射文件和 Caddy/systemd
示例见 [CaseScreen 自托管识歌 Relay](recognition-relay.md)。

## 采样、VAD 与内存边界

默认录音格式固定为 16 kHz、单声道、S16_LE。当前镜像参数使用 ALSA `plughw:audiocodec`，让 plug 层把审计到的多声道采集端转换为单声道；这个名称仍必须在每种真机上探测验证，不能仅凭镜像配置认定设备存在。状态机每轮只通过 `arecord` 的标准输出读取 1 秒短块，不创建音频临时文件；每块约 32 KiB，最多保留最近 10 秒约 320 KiB 的 PCM 环形窗口。

每个短块先执行本地能量 VAD。默认实现以 20 ms 帧去除直流分量，并结合 RMS、峰值与有声帧比例过滤静音、风扇底噪和偶发敲击。短块结束后会清零临时 PCM；环形窗口只在进程内存中存在，不写入 TF、日志或诊断报告。

行为约束如下：

- 窗口未满 10 秒时不发起识歌；
- 当前窗口没有足够有声内容时不联网；
- HTTP 请求在后台有界运行，不阻塞后续 1 秒短块和静音判断；
- 当前接受的歌曲连续出现两个静音短块时，在约 2–2.5 秒内把歌词时间轴推断为暂停，并清空旧识别环，避免恢复后拿暂停前音频识歌；
- 静音只能支持“可能暂停”的保守推断，无法区分播放器暂停、音量为零、静音段、耳机改路由或环境声消失；
- 暂停后连续两个有声短块可先本地恢复时间轴；后台仍会用后续有效识别结果低频复核并校准 offset，单个噪声块不会恢复。

## fingerprint 与 relay

正式低带宽部署强烈推荐有许可的 ARM32/ARMv7 fingerprint 提取器。提取器从 stdin 读取固定格式 PCM，只向 stdout 输出不超过 64 KiB、带算法和版本标识的紧凑声纹；中间文件和长期音频日志均被禁止。算法与版本必须和 relay 契约完全匹配。

仓库现在提供一个不包含第三方 SDK 的
[`tools/acrcloud_fingerprint_wrapper`](../tools/acrcloud_fingerprint_wrapper/README.md)。它先用
15 阶半带 FIR 把屏端 16 kHz PCM 低通降采样到 ACRCloud 官方轻量库要求的 8 kHz，
再动态加载部署者自行合法取得的 ARM32 `libacrcloud_extr_tool.so`。镜像补丁器可用
`--fingerprint-library` 把该共享库与提取器写入同一私有目录，但仓库和发行包不会复制
或授权官方二进制。静态 ELF/GLIBC 检查只能排除明显错误，仍需在实体屏上执行一次已知
音频声纹和 relay 匹配测试。

ARM32 提取器不是 readiness 硬门禁。未配置提取器时，运行库允许 PCM JSON 兼容回退，并要求探针、启动日志和文档明确标记它：10 秒、16 kHz、mono、S16_LE 的 JSON base64 约 427 KiB/次；歌曲稳定后默认 15 秒复核一次，平均上行约 28 KiB/s，未确认歌曲阶段可能更高。此配置可以启动，但不能称为低带宽最优模式。配置了真实提取器后会优先只传声纹；提取失败不会暗中回退 PCM。

relay 地址默认必须是 HTTPS：

- 禁止带用户名密码的 URL，禁止跨地址重定向，避免 Bearer token 泄露；
- 明文 HTTP 只允许显式本地调试，不属于可发布配置；
- 请求和响应都有大小、协议版本和超时限制；
- HTTP 429/503/504 的 `Retry-After` 会参与退避；
- relay 返回的标题、歌手、时长、置信度和偏移都要经过格式与范围校验。

默认在未确认歌曲时每 2 秒允许一次识别尝试，歌曲稳定后每 15 秒复核一次；首次歌曲或切歌默认需要连续两次相同稳定 ID 且置信度至少 0.78。第一份不同歌曲证据只冻结旧时间轴，第二份连续证据才切换，避免偶发误识别让歌词跳歌。

网络或 relay 失败时，识歌请求从 10 秒开始指数退避，最长 5 分钟，并尊重不超过上限的服务端 `Retry-After`。退避不会生成标题猜测；已有歌曲状态和缓存不会因一次网络错误被立即删除，但新歌仍需网络识别。

## 本机歌词时间轴

relay 返回“采样时刻对应的歌曲偏移”。状态机接受结果后把它转换为屏端本机锚点，并用进程的单调经过时间推进位置；歌词渲染不依赖每帧网络时间或持续上传音频。墙上时钟仍用于 TLS 证书有效期和请求时间校验，但运行中校时不应让已接受歌曲的歌词位置突然跳变。

有时间戳歌词按本机位置选择当前句和下一句；纯文本歌词不伪造滚动时间，固定显示“该首歌的歌词暂不支持滚动”。暂停推断后锚点冻结，连续有声恢复后先从冻结位置继续，后续识别再用新的 offset 校正。

## 平台身份不能由音频来源推断

fingerprint 匹配的是一版录音，不是播放应用。同一录音从 QQ 音乐、网易云音乐、本地文件或浏览器播放时，声纹没有可靠区别。因此 relay 返回的 `stable_id` 或 ISRC 只表示识歌目录身份，不能直接用于平台精确歌词。

QQ/网易云歌词链必须满足：

1. relay 或其后端具有服务端授权、官方目录关系或其他可靠的平台映射；
2. 返回规范的 QQ `songmid` 或网易云十进制歌曲 ID；
3. 明确设置 `native_id_verified=true`；
4. 屏端再次校验 ID 格式和用户配置的平台偏好；
5. 只向同一个平台的精确 ID 歌词接口请求。

`preferred_platform=qq|netease` 只能收窄希望使用的映射，不能把来源不明的录音证明成该平台。按标题、歌手、专辑或时长搜索并选择最像的候选属于猜测，必须失败关闭。没有可靠原生 ID 时可以保留识歌标题用于状态说明，但不能请求 QQ/网易云精确歌词。

## 登录态、歌词缓存与用户权益

屏端 direct 歌词请求可使用用户主动提供的 QQ/网易云登录态。登录态与 relay token 是两类不同凭据：relay token 只授权识歌中继，平台登录态只发往对应平台的 HTTPS 白名单主机。一次性导入文件成功后应删除明文源文件；登录态不得写入歌词缓存、主题或诊断报告。

登录只继承账号已经拥有的权限。它不会自动获得 VIP、绕过付费或地区限制，也不能用共享主账号或公共 Cookie 扩大权益。平台返回未登录或会员限制时，应在日志/状态页明确报告，歌词层保持隐藏；不得改用标题搜索规避授权。

歌词缓存按规范化的 `platform + track_id` 计算不可猜文件名，条目同时保存平台和原生 ID，读取时再次核对。缓存只包含歌词结果，不包含 Cookie、Authorization 请求头、relay token、PCM 或 fingerprint。镜像启动器应对文件数量和总大小设置上限，避免长期运行耗尽 TF。

## 启动硬件与信任门禁

启动 `standalone-recognition` 前必须逐项通过以下检查：

| 门禁 | 必须证明的事实 | 失败行为 |
|---|---|---|
| 架构与程序 | `casescreen-edge` 是目标机可执行的 ARM32/ARMv7 程序 | 不启动识歌，回原厂 |
| 麦克风 | ALSA 存在实际 capture card，指定 PCM 可完成 16 kHz mono S16_LE 短采样 | 不启动识歌，回原厂；采到静音本身不算设备故障 |
| 独立网络 | 物理接口提供默认路由；或显式桥模式下 `usb0`、`192.168.77.1`、DHCP/DNS 与链路状态全部匹配 | 不启动识歌，回原厂 |
| DNS | relay 主机能够正常解析 | 不启动识歌，回原厂 |
| 可信时间 | 系统时间处于可信范围，并有可持续的 RTC/NTP 或受控校时策略 | HTTPS 保持关闭，回原厂 |
| CA | 指定 PEM CA bundle 可解析且用于正常证书/主机名验证 | 禁止跳过 TLS 校验，回原厂 |
| relay | URL 为允许的 HTTPS 地址，协议和超时配置有效 | 不启动识歌，回原厂 |
| token | 逐屏可撤销 token 存在、权限受限且格式有效 | 不启动识歌，回原厂 |
| 上行模式 | 配置 fingerprint 时，ARM32/ARMv7 提取器可执行且 algorithm/version 与 relay 一致；未配置时明确报告 PCM 高带宽回退 | 已配置但无效时失败关闭；未配置时告警但允许兼容回退 |
| Theme | 驻留 Theme 与 1024×600 或 480×1920 目标严格匹配 | 不切换错误 Theme，回原厂 |

“存在 `/dev/snd/*`、`arecord`、`wpa_supplicant` 或 Wi-Fi 示例配置”只能证明镜像里有节点或用户态工具，不能证明实体器件、内核驱动、固件、天线、STA 连接或默认路由工作。原镜像也没有可证明可用的 CA bundle。门禁必须在每台真机启动时重新判断，并把不含 SSID、密码、token、Cookie 或音频的失败原因写入诊断文件。`br-lan` 等没有 `/sys/class/net/<name>/device` 的虚拟接口不能算物理网络；`ntpd` 进程存在也不能证明已经校时，只有成功同步后原子创建的时间 marker 才能通过可信时间门禁。

补丁器会安装一个只接受 BusyBox `ntpd` 有效 `ACTION=stratum` 且 stratum 为 1..15
的 hotplug hook。launcher 每次启动先用原镜像位于易失性 `/var` 的成功标记清理或重建
`/run/casescreen/time-synchronized`。只有发现已 up、带 gateway 默认路由、具有物理
`device` 节点且不是 RNDIS/USB gadget 的接口时，才最多等待 60 秒让 NTP 完成。显式
`usb-gadget-bridge` 模式则只接受补丁器固定创建的 `usb0` 和十六进制网关
`014DA8C0`（即 `192.168.77.1`）；普通 RNDIS、错误网关或断开的链路均不放行。

任意 USB/RNDIS 路由默认不能算“独立网络”。只有镜像明确选择 `usb-gadget-bridge`，并接到无需电脑、自己通过 Wi-Fi 提供 DHCP/DNS/NAT 的专用 USB Host 小桥时才属于独立部署。Windows USB 共享网络仍不符合 `standalone-recognition` 的独立运行定义。

专用桥的首个可验证实现、配置与电源限制见
[`deploy/waveshare-usb-bridge`](../deploy/waveshare-usb-bridge/README.md)。该链路不传视频帧或电脑
音频，只传屏端生成的声纹、识歌响应和首次歌词数据；Windows 主机资源占用为零。

## 镜像与回退

镜像补丁只允许作用于结构和原厂文件均符合预期的干净 7/8.8 英寸整盘 IMG，并使用独立输出文件，不能覆盖输入。补丁器保留原厂程序为 `/data/PCMonitorLinux.original`，写入运行程序、非秘密配置、CA、逐屏 token 和分辨率匹配的 Theme，并复验 GPT、ext4、文件内容、权限和分区外字节。

launcher 的基本原则是失败关闭：配置缺失、门禁未通过、`casescreen-edge` 无法执行、原厂显示桥失败或运行时异常时，停止识歌链并 `exec` 保留的原厂程序。回退是可恢复性保证，不是识歌真机验收证明。

## 与频谱功能的关系

屏端麦克风只服务于 `standalone-recognition` 的歌曲识别。项目中的频谱输入仍来自 Windows WASAPI shared-mode loopback，既不是屏端 ALSA 麦克风，也不会把识歌 PCM 变成频谱。没有 Windows 主机时，当前 WASAPI 频谱链不可用。

## 真机验收清单

发布前应分别在 7 英寸和 8.8 英寸实体设备完成并留存证据：

1. 枚举真实 codec/card/device、录音增益和采样格式，验证风扇噪声、安静房间与正常播放距离下的 VAD；
2. 记录 Wi-Fi 芯片、内核驱动、firmware、接口名、默认路由和断线重连；
3. 冷启动、断电、无 RTC 与 NTP 恢复场景下验证可信时间和 TLS；
4. 验证 CA、主机名、过期证书、错误 relay、撤销 token、429/503/504 和完全断网时均失败关闭或正确退避；
5. 验证 ARM32 fingerprint 输出与 relay 版本契约、带宽、CPU、内存、温度和长时间稳定性；
6. 使用同一录音分别从 QQ、网易云和本地文件播放，确认未授权映射不会伪造平台 ID；
7. 验证有缓存、无缓存、登录失效、会员歌词、切歌、静音、恢复和误识别时的显示与时间轴；
8. 验证缓存容量上限、异常断电后的 TF 一致性，以及每一种门禁/运行失败都能回到原厂程序。

在这些测试实际完成前，文档和发行说明只能描述“已实现并可测试的链路”，不能写成“7/8.8 英寸已通过独立识歌验收”。
