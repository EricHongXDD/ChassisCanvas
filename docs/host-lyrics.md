# Windows 主机歌词同步

本文仅描述正式 Windows 方案。歌曲状态、同平台取词和歌词计时都由
当前电脑完成；副屏只显示 USB 小包，不保存音乐平台登录态。

## 歌曲身份

Windows 主机按播放器使用其可验证的本机原生状态源：

- QQ 音乐最终只接受 `songmid`。CaseScreen 主进程使用查询和
  `PROCESS_VM_READ` 权限对 `QQMusic.exe` 做有界只读检查。只有
  `QQMusic.dll` 整体不超过 20 MiB 时才完整扫描；模块超限、任一分块
  读取失败、负缓存候选或多进程证据不一致都会整轮失败关闭，不接受
  前缀结果。内存中的数值 songId、曲名、全部歌手、专辑、时长、位置和
  播放状态还必须与同一轮 GSMTC 一致，才按 songId 换取 songmid，并用
  平台单曲详情再次交叉核对。该路径不写进程内存、不注入 DLL，功能已
  内置于 `CaseScreen.exe`；只需 QQ 音乐客户端和原有 USB 副屏，不需要
  购买其他硬件或安装辅助程序。
- 网易云音乐只接受官方 Windows 客户端当前播放结构中的规范十进制歌曲
  ID。CaseScreen 主进程只申请查询和 `PROCESS_VM_READ` 权限，对
  `cloudmusic.exe` 所加载的 `cloudmusic.dll` 做有界特征定位，然后读取
  当前歌曲 ID、秒级位置、时长和播放/暂停状态。再以该 ID 为键，从官方
  客户端本机 `playingList` 的有界稳定快照中读取同 ID 的曲名、全部歌手、
  专辑和时长；不会拿标题反查 ID。同 ID 条目元数据冲突、候选进程/特征/结构
  不唯一、任一有界读取失败，或可用 GSMTC 与原生证据不一致时，都整轮失败
  关闭。该功能内置于 `CaseScreen.exe`，不写进程内存、不注入 DLL、不打开
  调试端口，也不需要关闭或重启网易云。

两种平台都不会读取 `webdb`、历史或窗口标题来推断歌曲 ID。网易云只用
内存中的当前 ID 定位 `playingList` 同 ID 元数据，其他条目不会成为候选。
客户端更新导致已验证结构失配时，只停止该平台的在线歌词，不会退化为猜歌。

标题、歌手或时长的相似搜索不是原生 ID。缺少可靠 ID 时精确取词
失败关闭，不选择“最像的歌”。

## 取词、权限与缓存

主机按 `platform + track_id` 从同一平台请求 LRC/QRC 或纯文本歌词，
并缓存在 Windows 配置目录。公开歌词在 `not_configured` 状态下也可
直接请求；只有平台实际拒绝后才标记 `needs_login`（需要登录或会员权限）。

打开平台官方网页不会自动连接 CaseScreen 或读取浏览器会话。用户登录后
仍需主动导出并在主机导入一次 `cookie.txt`。该文件只是本地导入载体，
不是只能使用一次的 Cookie；成功导入后主机会跨启动复用，只有平台过期、
撤销或拒绝时才需更新，源文件不会被持续读取。会话内容使用 AES-GCM 加密，
密钥以 `CSPK2` 格式由当前 Windows 用户 DPAPI 保护；旧版 32 字节密钥
会自动原子迁移，已有 AES-GCM 会话数据不变。登录只继承账号已有权益，
不会自动获得 VIP 或绕过地区限制。

登录态、Cookie、平台密钥、原生歌曲 ID 和整份歌词都不会下发副屏。

## 滚动与暂停

有时间轴的歌词以播放器位置和播放状态为事实源：

- 播放：主机以播放器锚点和本机经过时间投影位置，越过下一句时换行；
- 暂停：锁定播放位置、保留当前/下一句与 `LV=1`、停止主机换行计时器，并发送一次 `Playing=false`；启用进度轨时同一事件携带最终进度；
- 恢复：采用播放器的新锚点继续主机计时，并发送一次 `Playing=true`；
- 拖动：立即使用新位置重新选择当前句和下一句；
- 纯文本：不伪造时间轴，显示“该首歌的歌词暂不支持滚动”。

## 显示样式与协议边界

工作台可为歌词选择流光播放器、卡拉 OK、经典双行或极简样式，并设置
当前/下一句字体、字号、颜色、字重、描边、阴影、柔光、面板、淡入和进度轨。
酷冷由 Windows 合成帧，可按主机已知的句内进度渐进高亮；微雪把
字体、面板和多层文字效果编译进 TF 驻留 Theme，原厂控件仍只显示主机选好的
当前句与下一句。启用微雪进度轨时只额外绑定一个主机已计算的整数进度短键。
频谱可见时直接并入约 9～10 Hz 的完整频谱 `QStringMap`；频谱不可见时才独立发送，
最高 20 Hz，并在可见步进未变化时去重。
进度按原生轨道可见像素去重，发送较慢时只保留最新唤醒，不积压历史位置。
其他显示设置不增加运行期字段，也不会把连续播放位置或
整份歌词发送给副屏。

## USB 歌词小包

微雪运行期只接收当前显示需要的字段：

```text
CaseScreen_LyricsCurrent       当前句
CaseScreen_LyricsNext          下一句
CaseScreen_LyricsCurrentAtMs   当前句起始时间（毫秒；未知时为空）
CaseScreen_LyricsNextAtMs      下一句起始时间（毫秒；未知时为空）
CaseScreen_LyricsPlaying       true / false
LV                             0 隐藏整层；1 显示（暂停仍为 1）
LFP                            可选；新版 Theme 当前句 0～10000 细进度
CaseScreen_LyricsProgress      兼容旧 Theme；当前句 0～100 整数进度
```

- 当前句和下一句各最多 256 个 Unicode 字符；
- 六字段歌词状态只在双行文字、对应时间戳、播放/可见状态改变，或重连/Theme 重载后需要补状态时发送；
- 只有驻留主题启用进度轨且歌词有时间轴、正在播放时才计算 0～10000 细进度；频谱可见时 `LFP` 合并进约 9～10 Hz 的完整频谱 `QStringMap`，频谱不可见时才独立发送且最高 20 Hz；旧键不进入频谱包，只在跨整百分比或状态事件时单独发送；暂停事件发送最终值后立即停止；
- 切歌取词中、无歌词或当前句尚未出现时以内部 `LyricsClear` 标记发送显式清空包：`LV=0`、空双行、空时间戳、`Playing=false` 和新旧进度归零；暂停且已有当前句时保持 `LV=1` 与原双行，纯文本不可滚动时仍以 `LV=1` 显示固定说明；
- 不发送连续播放位置、整份歌词、歌曲 ID、Cookie 或 PCM；合并只复用主题本来就需要的量化频谱包，不传输音频数据；
- 已获得设备 ACK 的完全相同包会跳过；
- 断线或 Theme 重载后清空去重状态，只补发一次当前值；
- 关闭歌词时只发一次 `LV=0`、空文字、空时间戳、`Playing=false` 和进度归零的复位包。
- 旧版驻留 Theme 没有可见性编译版本时不能直接恢复。模板库/轮播激活会先重编译；普通当前主题在升级后需于编辑器重新应用一次。若源素材已经丢失，界面会要求重新选择素材并保存，而不是继续显示烘焙在旧背景里的歌词底板。

当前原厂 PCMonitorLinux/Theme 没有整份歌词解析器；CaseScreen Theme 消费
两个文本键和可选细进度键，三个时间/播放元数据键由旧固件安全忽略。当前
正式版不会下发整份歌词，也不提供在屏内另行部署歌词解析服务的设置入口。
细进度仍使用原厂整数标量控件，不要求修改屏内系统；旧 Theme 继续消费兼容键，重新应用新版 Theme 后启用 0～10000 细进度。正式版继续使用
README 列出的 clean expanded 8GB 镜像，不需要 edge-display 代理镜像。

酷冷固件未发现同等的驻留键值控件接口。它显示歌词时仍由 Windows
合成变化后的 JPEG 帧。
