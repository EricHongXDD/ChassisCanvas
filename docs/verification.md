## beta.13 独立 USB/Wi-Fi 小桥

beta.13 为微雪 `standalone-recognition` 增加了无需电脑的显式
`usb-gadget-bridge` 网络模式。两款原始镜像和两款 8GB 展开镜像的内核/rootfs 哈希一致；
内核没有 PPP、SLIP、TUN、USB Host 网卡或常见 Wi-Fi 驱动，但已静态编入 configfs ACM、
RNDIS、`u_ether`，用户态已有 BusyBox `udhcpc` 与 `/usr/share/udhcpc/default.script`。
因此选用“屏幕 USB Device（ACM+RNDIS）→ 独立 USB Host/Wi-Fi 小桥”而不是重编内核或
占用电脑音频输出。

镜像补丁器现在可通过 `--network-mode usb-gadget-bridge`：

- 保留原 `/data/serial_uart.sh` 为 `serial_uart.sh.original`；
- 一次性建立 ACM+RNDIS 复合 Gadget，失败时恢复 ACM-only；
- 屏端用 30 秒有界 DHCP 获取地址、默认路由和 DNS，不运行相反方向的私有 DHCP server；
- 只接受 `usb0` 上严格指向 `192.168.77.1` 的默认路由；物理模式仍拒绝任意 USB/RNDIS；
- 继续要求真实链路 up、DNS、NTP 成功 marker、CA、HTTPS relay、逐屏 token、ALSA 和 Theme；
- 写入后逐文件、权限、ext4、GPT 与 UDISK 外字节复验，原厂显示和串口脚本均可回滚。

`deploy/waveshare-usb-bridge/configure_raspberry_pi.sh` 为 Raspberry Pi OS Bookworm/
NetworkManager 建立按固定 Host MAC 匹配的 shared IPv4 配置；DHCP、DNS 转发和 NAT 由
NetworkManager 提供，Wi-Fi 密码仍由操作系统管理。Python 补丁器/发行 ZIP 测试 35 项通过
（1 项需要外部 mke2fs 的集成夹具而跳过），Go 全量测试与 `go vet` 通过；镜像补丁器生成的物理/
专用桥启动器、Gadget 脚本和 Raspberry Pi 脚本共四份均已通过真实 `bash -n`。发行 ZIP
还逐条读取全部条目并按内部 `SHA256SUMS.txt` 复核；Linux 二进制和 `.sh` 均为 Unix
`create_system=3`、`0755`，普通文件为 `0644`；未包含 `.so`、CA、Cookie、token 或私钥文件。

`deploy/waveshare-usb-bridge/esp32-s3/` 同时保存了默认失败关闭的量产方向实验骨架。
乐鑫官方 RNDIS Host 对复合设备要求 RNDIS-first，而 beta.13 为保持串口兼容使用
ACM-first；因此该骨架未编译、未烧录、不能替代当前 Linux/NetworkManager 小桥。

这些结果证明镜像和桥配置链已实现，不替代实体屏的 RNDIS 枚举、电源、ALSA、真实 relay、
QQ/网易云强映射与歌词端到端验收。没有这些真机/凭据证据时仍不能把镜像称为最终可用成品。

Windows `0.3.0-beta.13` 随后替换正在运行的 beta.12 服务，继续使用同一默认 Console
播放端点。微雪 7 英寸和酷冷至尊均自动重连，微雪报告剩余 `762314752` 字节。
播放三次 Windows 系统提示音时，实测峰值 `0.7932`、最多 18 个频带同时非零，
结束 900 ms 后峰值和 32 个频带全部归零。该复验没有使用麦克风、虚拟声卡或第二输出设备。

## beta.12 增量验收

beta.12 在 beta.11 已完成的系统回放频谱基础上再次执行在线实测。当前服务监听默认
Console 端点 `扬声器 (3- XIBERIA S21 Wireless 7.1)`；静音时峰值和 32 个频带全部
为零。播放三次 Windows 系统提示音时峰值达到 `0.7946`、最多 18 个频带同时非零，
700 ms 后再次全部归零。当前微雪主题含条状和环状两个 `source=system` 图层；主题按
新协议重新编译并应用后设备返回 `waveshare-7: ok`，再测峰值 `0.7874`、18 个频带
变化并正确归零，微雪与酷冷均保持在线。该链路不打开麦克风、不改变默认输出，也不传
PCM；微雪仍只接收 10 FPS 上限的量化短键小包。

最终审计同时修复了两条会造成“主机频谱在变、实体屏不动”的状态路径。主题上传或
重载失败时，新 manifest 现在只进入待重试区，旧主题、动态键和渲染器继续作为已确认
状态；只有设备 ACK 成功后才提交。后续频谱/遥测 ACK 也不会清除尚未解决的主题错误。
全局应用发生部分失败时，仅成功设备采用新主题，失败设备不会被错误切换。断线重连会
优先重试待应用主题，成功后再切换动态键。Windows 发现逻辑也会用当前 SERIALCOMM
端口过滤 Enum\USB 的历史 COM 残留；只有“唯一已配置微雪 + 唯一在线端口”时才迁移
COM 号并保留逻辑设备 ID，多屏或多候选时不猜测身份。

`0.3.0-beta.12` 修复版启动后再次以真实系统提示音验收：峰值 `0.7924`、最多 18 个
频带同时非零，声音结束后峰值和全部频带归零；当前主题的条状、环状图层均为
`source=system`，微雪在线且没有传输错误。

独立识歌侧新增可部署的 `recognition-v1` relay：设备 Bearer token 只以 SHA-256 摘要
保存；真实 ACRCloud provider 按官方签名协议提交 PCM 或紧凑 fingerprint；只有
`stable_id`/ISRC 精确命中管理员映射时才返回经验证的 QQ `songmid` 或网易云数字 ID。
provider 自带的平台 ID、标题搜索和相似候选均不能升级为原生 ID。屏端和 relay 的
deterministic 端到端测试覆盖 PCM、fingerprint、错误 token、两次确认、QQ 强映射、
单调时间轴、静音暂停与有声恢复，并连续运行 50 次通过。

发布审查补齐了拆分强证据冲突、响应协议头/媒体类型/256 KiB 上限、未知字段和尾随
JSON、HTTP 504 退避、fingerprint 标识长度、64 位十六进制 token 大小写保持以及
ACRCloud wrapper/共享库强配对。ARMv7 声纹包装程序使用 15 阶半带 FIR 把 16 kHz
PCM 转为官方轻量库所需的 8 kHz，构建结果只要求目标机已有的 ARM hard-float、
`GLIBC_2.4`、`libc.so.6` 和 `libdl.so.2`；官方共享库不进入发行包。

两份原图与两份干净 8 GB 扩容图的静态审计确认：7 英寸和 8.8 英寸使用相同 rootfs
与 kernel，扩容仅增大 UDISK/GPT；内核没有常见 SDIO/USB Wi-Fi 驱动，固件目录为空。
当前 7 英寸在 Windows 只枚举 ACM 串口，没有 RNDIS/USB 网卡；7 英寸 GMAC 缺少实体

## beta.11 增量验收

beta.11 将条状和环状频谱的输入统一改为 Windows 默认 Console 播放端点的 WASAPI shared-mode loopback。它读取系统即将送往扬声器或耳机的最终混音，不打开主机或副屏麦克风，不创建虚拟声卡，不改变播放器输出设备，也不使用独占模式。主机只执行 Hann 窗 FFT；微雪只接收量化后的 `0..100` 短键值，不传 PCM、复数频谱或完整画面。

本轮补齐了两个会产生假波峰的边界：WASAPI 停包超过 80 ms、时间倒退、采样率变化或报告 `DATA_DISCONTINUITY` / `TIMESTAMP_ERROR` 时，会清空旧 FFT 窗口和平滑状态并立即发布零帧；多声道 PCM 改为线性等权下混，不再用 RMS 加最强声道符号的非线性折叠制造原音频中不存在的谐波。对应回归测试覆盖“长停包后只恢复一个短静音包”和左右声道分别为 440/880 Hz 的场景。

最终二进制在真实默认端点 `扬声器 (3- XIBERIA S21 Wireless 7.1)` 上运行。播放四次 Windows 系统提示音时 API 观察到频谱峰值约 `0.794`、最多 18 个频带同时非零；播放前与声音结束 600 ms 后峰值和全部 32 个分析频带均为零。微雪 7 英寸 COM3 与酷冷至尊在测试前后保持在线。5 秒连续提示音负载期间，整个 CaseScreen 后台进程约占 24 线程整机 `0.052%` CPU，工作集约 `38.2 MiB`，未改变系统声音输出。

微雪条形与环形控件继续共用 38 个短键，默认每 100 ms 最多发送一次、满幅应用层包为 802 字节；ACK 后相同载荷去重，静音零包确认后不重复发送，串口忙时实时频谱包不排队。酷冷没有同类驻留动态键接口，仍由主机合成变化后的 JPEG 帧，但同样不会接收原始音频。

本轮还完成了条件式 `standalone-recognition` 软件链：屏端 1 秒 ALSA 短块、10 秒 RAM 环、VAD、异步 HTTPS 识歌、连续确认、静音暂停/有声恢复、本机单调歌词时间轴、QQ/网易云强验证原生 ID、TF 歌词缓存、两阶段硬件门禁和原厂回退。ARMv7 运行程序已经交叉编译为 ELF32 little-endian `EM_ARM=40`。镜像补丁器只允许修改干净镜像的第 6 个 UDISK，并验证 GPT、ext4、权限、Theme、原厂备份和分区外哈希。

`standalone-recognition` 尚未生成可宣称可用的新 8GB 镜像：正式构建还需要真实 HTTPS relay URL、逐屏 token、CA，以及每种实体屏的麦克风、独立网络、可信时间验证；可选有许可的 ARMv7 fingerprint 提取器用于低带宽。没有提取器时允许明确的 PCM 兼容回退，但 10 秒窗口的 JSON base64 约 427 KiB/次，不能称为低带宽模式。现有 7/8.8 英寸扩容基础镜像保持不变。

最终源码验证：

- `go test ./...`：全部通过；
- `go vet -unsafeptr=false ./...`：通过；标准 `go vet ./...` 仍报告既有 Windows FFI 的 `unsafe.Pointer` 警告；
- Python 镜像补丁测试：27 项中 26 项通过，1 项真实 ext4 冒烟测试因本机没有 `mke2fs` 跳过；
- Windows GUI 两个入口均为 PE Subsystem 2，发布 ZIP 包含新增的屏端识歌说明；
- ARMv7 运行程序通过补丁器的架构和所需命令行能力校验。

## beta.10 基线结论

beta.10 的微雪歌词主链路采用“主机处理、USB 小包同步、屏内驻留主题显示”：

1. Windows 主机读取 QQ 音乐或网易云音乐的当前播放状态；只有平台来源能够确认原生歌曲 ID 时，才把该 ID 用于同平台取词。QQ 只由 CaseScreen 主进程的 `QQMusic.exe` 有界只读内存适配器取得 songId，再精确换取并验证 songmid；网易云只由 CaseScreen 私有管道读取官方客户端 `window.__autotest__`。
2. Windows 主机在同一平台获取并缓存歌词，在本机完成时间轴匹配，生成当前句、下一句及校时字段。
3. 微雪驱动通过现有 USB 串口的 `CommandSystemData` 命令发送 `QMap<QString, QString>` 小包。
4. TF 卡中的驻留 `.Theme` 使用动态键显示当前句和下一句；背景、字体及其他静态资源不随歌词周期重复上传。

当前验收**不再依赖** EdgeSync、RNDIS、屏端 HTTP 服务、`source-push`、屏端平台登录或屏端直接联网取词。屏端不保存 QQ/网易云登录态，不需要 DNS、CA 证书、Wi-Fi，也不使用麦克风识歌。歌词识别来自原电脑播放器状态；系统回放环回只服务于可选频谱，不属于歌词识别输入。

上述“小包 + 驻留主题”能力仅适用于支持原生动态键的微雪协议。酷冷协议仍按设备能力使用主机合成帧，不能据此宣称同等的小包歌词能力。

## 自动测试与静态检查

本轮在当前工作树执行并通过：

- `go test -buildvcs=false -count=1 ./...`
- `go vet -buildvcs=false -unsafeptr=false ./...`
- `go test -buildvcs=false -count=1 ./internal/lyrics ./internal/service ./internal/telemetry ./internal/device/waveshare`

定向测试覆盖以下当前 1.0 行为：

- 当前句、下一句、两句起始时间、`playing` 状态和可见键 `LV` 进入微雪基础 `QStringMap` 小包；启用驻留进度轨时新版 Theme 绑定短键 `LFP`（0..10000），并保留 `CaseScreen_LyricsProgress`（0..100）兼容旧 Theme，平台 ID 与连续播放位置仍只留在主机。
- 取词中、无歌词或当前句尚未出现时，主机以内部 `LyricsClear` 标记生成显式清空包：`LV=0`、双行与时间戳为空、`playing=false`、新旧进度归零，不再显示等待占位；只有真实歌词行才发送对应起始时间。
- 歌词时间轴在播放时按锚点推进，暂停后固定在暂停位置，恢复播放后从新锚点继续。
- 只有被平台来源确认的原生歌曲 ID 才会用于主机同平台取词；任何平台 ID 都不会进入副屏小包。
- 当前媒体轮询一旦缺少来源原生 ID，就不会沿用上一轮 ID；既有在线歌词会清空并重新失败关闭。QQ `songmid` 的大小写属于歌曲身份的一部分，不做小写归并。
- QQ 内置适配器只在 `QQMusic.dll` 整体不超过 20 MiB 时完整只读扫描；模块超限、任一分块读取失败、负缓存候选或多进程证据冲突都整轮失败关闭，不接受前缀结果。内存 songId、标题、全部歌手、专辑、时长、位置与播放状态还必须和同一轮 SMTC 全部一致。随后只按 songId 请求单曲详情，并严格核对返回 songId、songmid、标题、全部歌手、专辑和时长，不使用搜索词。
- 同平台在线冒烟测试通过：网易云歌曲 ID `186016` 返回 62 行同步歌词，QQ songmid `0039MnYb0qxYhV` 返回 63 行同步歌词；QQ songId `97773` 另行精确映射到该 songmid。
- 生产入口、工作台和配置校验均不再提供酷狗/搜狗标题搜索；旧值只迁移为严格 `auto`，当前 Chrome 等未知来源不会再发起标题联网猜歌。
- 纯歌词包不附带每秒变化的日期/时钟字段，也不会在硬件遥测不可用时伪造 CPU、GPU 或内存零值。
- 单行歌词最多保留 256 个 Unicode 字符，超限时以省略号收尾；包含两行歌词和校时字段的最坏用例必须小于等于 4 KiB。
- 微雪驱动只在收到 ACK 后记录最近一次有效载荷。完全相同且已经 ACK 的包不会重复写入 USB；暂停、恢复、拖动、切歌或换行会触发新的事件包。
- 后台容量查询可被新歌词事件取消，Windows 串口同步读取使用最长 50ms 的物理读取片；默认只在连接或用户手动刷新时查询容量，不在歌词播放期间周期争用串口。
- 微雪小包设备重连并重载主题后立即补发当前歌词，不受最长 60 秒的普通遥测间隔影响。
- 关闭歌词会显式发送 `LV=0`、空文字、空时间戳、`playing=false` 和进度归零；成功发送后不再重复，失败时保持待重试状态。暂停且当前句非空时则保持 `LV=1` 与原双行，只冻结进度。
- 主题文件远端路径与 CRC32 相同时跳过资源上传，只执行主题重载；静态图片、字体和主题文件不会作为歌词更新反复传输。
- Windows 音频源使用默认 Console 播放端点的 WASAPI shared-mode loopback；切换默认输出会触发立即重连，端点底噪低于固定门限时跳过 FFT 并输出全零频带。
- 微雪条状/环状频谱重新编译为 type 102 主机数据控件，旧 `device_mic` 配置迁移到 `system`，不再生成 type 107/108 屏端麦克风控件。
- 默认 18 条柱状和 32 段圆环共享 38 个短键并合并为一个包；满幅完整包固定为 802 字节。旧版 150 个长键约 5972 字节，已不再由生产频谱路径发送。
- 频谱关闭、采集停滞或图层隐藏会显式归零；ACK 后的重复零包不再发送，串口锁繁忙时丢弃实时帧且不误记为已送达。

缓存重置路径已有专门的驱动回归用例：建立连接、成功重载主题、主动关闭和断线重连都会清空最近一次动态载荷，确保重连或换主题后的第一包不会被误判为重复包；用例也覆盖 ACK 后重复包去重和暂停后状态变化重新发送。

## 微雪歌词小包字段

歌词状态事件可包含以下专用字段：

| 字段 | 含义 |
| --- | --- |
| `CaseScreen_LyricsCurrent` | 当前句文本 |
| `CaseScreen_LyricsNext` | 下一句文本 |
| `CaseScreen_LyricsCurrentAtMs` | 当前句起始时间，毫秒 |
| `CaseScreen_LyricsNextAtMs` | 下一句起始时间，毫秒 |
| `CaseScreen_LyricsPlaying` | `true` 表示播放，`false` 表示暂停 |
| `LV` | `0` 隐藏整个歌词层，`1` 显示；暂停且当前句非空时仍为 `1` |
| `LFP` | 可选；当前句 `0..10000` 细进度，新版 Theme 的进度轨绑定此短键 |
| `CaseScreen_LyricsProgress` | 兼容旧 Theme 的 `0..100` 整数进度；跨整百分比时附带 |

歌词专用小包不再包含 `source`、`track_id`、`position`、`position_known` 或 `lyric_mode`。QQ `songmid` 与网易云数字 ID 只用于 Windows 主机上的同平台取词，既不下发副屏，也不允许标题模糊搜索结果替代。

主机默认每秒观察一次播放器，包含 `LV` 的基础六字段仍采用事件型发送：只有当前句、下一句、两句时间戳、`playing` 或可见性变化时才产生新载荷。若当前主题启用了驻留进度轨，频谱可见时会把 `LFP` 合并进约 9～10 Hz 的完整频谱 `QStringMap`；无频谱时才独立发送且最高 20 Hz，并按原生轨道可见像素去重。旧进度键不进入频谱包，只在跨整百分比或状态事件时单独发送。检测到暂停且当前句非空时，主机保留双行与 `LV=1`，停止位置投影并补发最终状态，随后不再周期发送。检测到拖动、恢复播放、切歌、可见性变化或歌词换行后立即产生新载荷。

当前驻留主题直接消费当前句、下一句、两句时间戳、`playing`、`LV` 和可选的量化进度整数。`LV=0` 会隐藏文字、面板、边框、样式装饰与进度底轨；纯文本歌词仍以 `LV=1` 显示“该首歌的歌词暂不支持滚动”。逐句选择与连续位置计算均留在主机，屏端不运行歌词抓取器或播放器。

## QQ 音乐与网易云音乐边界

平台登录和歌词请求全部发生在 Windows 主机。若官方歌词接口因账号或 VIP 权限拒绝访问，工作台应在主机侧引导登录并报告真实错误；Cookie、令牌和完整歌词库都不传给副屏，副屏只接收当下需要的少量显示字段。

| 平台 | 当前状态 | beta.10 验收边界 |
| --- | --- | --- |
| 网易云音乐 | 已实现 CaseScreen 私有匿名管道 → 唯一 `orpheus://` 页面 → 固定 `window.__autotest__` 表达式 → 数字 ID、媒体字段、状态与时间轴。没有 TCP 端口，不查询 `webdb`、队列、历史或窗口标题。 | NUL 分帧、target/会话、限长、超时、暂停及失败关闭已有自动测试；CEF 91 真机管道与播放/暂停/拖动仍需按 `windows-verification.md` 的门控完成。 |
| QQ 音乐 | 已实现内置 `QQMusic.exe` 有界只读内存 → 精确单曲详情 → 全字段交叉验证 → songmid → 同平台歌词。只申请查询/读权限，不写内存、不注入 DLL、不需要独立桥；仅当整个模块不超过 20 MiB 时完整扫描，songId 映射使用固定 512 首的有界主机内存缓存，不进入状态 JSON 或 USB 包。 | 在线实测 `songId=97773` 得到 `songmid=0039MnYb0qxYhV`、晴天/周杰伦/叶惠美/269 秒；没有使用标题搜索。模式、边界与失败关闭已有自动测试；真实客户端的特征码兼容、切歌、暂停/恢复和登录场景仍须逐版验收。 |

这里的“支持 QQ 音乐、网易云音乐”指软件已有两平台主机侧歌词能力和严格的 ID 契约，不等于两平台真实客户端均已在本机通过。网易云需要补私有管道及正在播放状态的端到端核对；QQ 需要验证当前客户端版本的只读结构、真实切歌与播放状态。SMTC `Genres` 注入标记不属于正式歌曲身份路径。

## 实机与设备边界

COM3 微雪 7 英寸已由 beta.10 重新应用当前主题，API 返回主题加载成功且设备保持在线、无传输错误。实际落盘的 `waveshare-theme-d89ba7567e01dfae42366e76.Theme` 已由解析器核对：63 个控件中有 50 个主机频谱 type 102 控件、38 个去重音频键，type 107/108 屏端麦克风控件均为 0。刷新容量后设备报告总量 803 MiB、已用 76 MiB、剩余 727 MiB（90.5%）；这是当前已分配文件系统的可上传容量，不把 TF 尾部未分配空间误报为可用。

本机 WASAPI 受控测试在空闲时采集 239,040 个样本、峰值约 `0.000030519`，正确低于静音门限；播放 Windows 系统提示音时在 8,160 个样本内得到峰值 `0.006179810`，真实信号硬断言通过。另行比较 Console 与 Multimedia 角色时，两者在本机指向同一端点并分别捕获峰值 `0.165100098`。beta.10 重新应用主题后播放五次系统提示音，音频引擎与 COM3 均保持运行且无错误。进程 I/O 从静音基线约 1.18 KiB/s 升至有声窗口约 9.79 KiB/s，衰减后回到约 1.18 KiB/s；该增量与 38 个短键、约 840 字节含包头、10 FPS 的发送模型一致，证明实际 WASAPI → FFT → COM3 小包链路在声音期间改变数值，静音归零后停止重复高频写入。五秒有声负载下后台服务约占单个逻辑核 0.92%（折算整机 24 线程约 0.038%），工作集约 43.3 MiB；桌面工作台因持续绘制可视化预览另占整机约 0.763%，关闭工作台不会停止后台服务。

微雪 8.8 英寸在本轮仍未在线。480×1920 主题编译和布局测试通过，但尚未完成串口握手、驻留主题应用、小包字段显示、暂停冻结或 TF 容量真机核对。

beta.10 发布前仍需补做：

- 在物理屏幕上继续人工核对频谱静音归零、音乐响应，以及歌词当前句、下一句、切歌、拖动进度、暂停、长时间暂停和恢复播放的视觉效果。
- 断开并重新插入屏幕、重新应用主题后，确认首包必定重发且不会保留旧歌词。
- 网易云音乐处于真实播放状态时，确认只读适配器得到来源确认的数字 ID，并完成同平台歌词与屏幕显示闭环。
- 安装现代 QQ 音乐后，在记录的客户端版本上验证只读结构定位、切歌、暂停、恢复和登录/VIP 场景；另可选验证 SMTC ID 标记优先路径。
- 8.8 英寸设备在线后重复上述关键用例。

## 历史实验记录（不属于 beta.10 当前验收）

以下能力曾在 beta.6 / beta.7 原型阶段测试，记录仅用于追溯，不作为当前产品路径或发布结论：

- EdgeSync 曾监听独立端口并使用配对令牌，验证过紧凑的当前播放响应和按平台 ID 获取歌词的响应大小。
- ACM+RNDIS、PTY 协议桥、屏端网络服务、屏端 setup 页面及镜像内 ARM 程序曾有离线或自动测试。
- `casescreen-source-push` 曾用于把来源歌曲 ID 推给屏端服务；屏端直接联网、直接取词和平台登录也曾作为实验设计。
- beta.6 扩容镜像和补丁器曾完成 ext4、分区哈希、原脚本备份及整盘镜像检查。

这些历史组件即使仍保留源代码或旧产物，也不得用于证明 beta.10 需要屏端联网、RNDIS、屏端账号、麦克风或后台歌词服务。当前验收只认 Windows 主机取词与 USB 小包同步链路；新镜像若预置驻留主题，也不应注入或启动上述网络实验组件。
